## Why this set is held out

Delivery 001 was built from **31 Aug – 6 Sep**. This set is the week before, deliberately, because Claude picked Delivery 001 and cannot also grade it.

**This is not a training set, and the system does not learn from it.** No weights, no feedback loop, no personalisation. It answers one question, once:

> Does any ranking beat plain reverse-chronological order at picking five things worth Barbara's attention?

D-11 says that if the answer is no, the prioritisation layer gets **deleted**, and deleting it counts as a good outcome. So this set exists to give a ranker something to fail against.

If Barbara later wants a system that adapts — the interest profile under D-10, taught by the "less like this" signal — that is a separate mechanism, and it would need its own held-out set to prove it improved anything. Do not conflate the two.

### What the test now covers, and what it still does not

With promotional items included, this set exercises **relevance ordering and promotional filtering together**, which is closer to the real job than the earlier field-adjacent-editorial sample was. It still does **not** test where the field boundary belongs (question 11), how a Source is identified when the sender address is not the publication (question 12), or which delivery addresses count (question 10).

**The test got easier for the ranker, and that is worth saying out loud.** An earlier draft of this file argued that prefiltering made reverse-chronological a *stronger* opponent. That was true of the prefiltered sample and is now obsolete: on the honest corpus, two of the baseline's top five are a webinar promotion and an automated paper recommendation. Reverse-chronological is weaker here than it looked, so clearing it is a lower bar. **Set the threshold with that in mind** — a ranker that merely avoids promotional mail will beat this baseline without demonstrating any judgment about relevance.

## Protocol, in order

1. **Label first, before any ranker output is visible.** For each item below, mark `Y` (worth one of five slots) or `N`. No middle value; the cap forces a binary.
2. **Write the threshold down before comparing.** Fill in the blanks below and commit them. A threshold chosen after seeing results is not a threshold.
3. **Baseline:** the five most recent items at delivery time — reverse chronological, no judgment. Precomputed below.
4. **Compare.** Ranker top five versus baseline top five, scored against the labels.

### What Barbara labels from

**Source, subject line, and preview text — the columns below, and nothing more.** This matches what the picker saw when it built Delivery 001 ("picked from subject lines and preview text, not from the full article text"), so the labels and the ranker face the same evidence. Do not open the original articles in order to label; richer evidence than the ranker gets would penalise it for not knowing what it could not know.

Preview text is not uniformly informative, and that is a property of the source rather than a signal about the item: **HackerNoon's preview is identical boilerplate across all seven of its items**, so those are effectively title-only. Academia.edu's previews name the paper of hers that triggered the recommendation. LinkedIn truncates mid-sentence. The handicap is symmetric — the ranker sees the same text.
